# PH1 Newsroom — Instructions for Claude Code

This repo hosts the PH1 broadcast site, published via GitHub Pages.

## When the user asks to "update the site," "sync videos," "push my
## changes," or similar

1. Run: `python3 sync_videos.py`
   - This reads `videos.xlsx`, regenerates `data.js` from it, and
     commits + pushes automatically.
2. Report back plainly what happened: how many videos were synced,
   and the exact text of any warnings the script printed about
   skipped rows (missing category, unreadable link, etc.) — the user
   isn't a developer, so translate warnings into plain instructions
   like "row 6 in your spreadsheet is missing a category, add one and
   run it again."
3. If the script says a push failed for an authentication reason,
   walk the user through the one-time GitHub sign-in described in
   SETUP.md — don't just paste the raw git error at them.

## Important
- **Never hand-edit `data.js` directly.** It's fully regenerated by
  `sync_videos.py` from `videos.xlsx` every time that script runs, so
  any manual edit gets silently overwritten on the next sync. If
  `data.js` needs to change, either the fix belongs in
  `videos.xlsx`, or in `sync_videos.py` itself (e.g. if the user
  wants to change site-wide settings like the tagline or category
  list, edit the `SITE_BLOCK` string in `sync_videos.py`).
- If `sync_videos.py` fails with an import error mentioning
  `openpyxl`, run `pip3 install openpyxl` and try again.
- The user is a teacher, not a developer. Keep explanations plain,
  avoid jargon, and don't show raw stack traces or git internals
  unless specifically asked — summarize what went wrong and what to
  do about it instead.
